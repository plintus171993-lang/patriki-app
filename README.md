# Патрики Паб — приложение доставки

Одна кодовая база для трёх вариантов:
- **iPhone и любой браузер** — веб-приложение (PWA) на GitHub Pages, ставится через «На экран Домой»;
- **Android** — APK, собирается автоматически в GitHub Actions;
- **Управляющий** — скрытая админка внутри того же приложения.

Сервер — Supabase (база, вход управляющего, фото меню). Заказы приходят в админку со звуком и в Telegram.

## Как попасть в админку
Главная → кнопка «i» (Информация) → внизу строка «© 2026 «Патрики Паб»» → **5 раз быстро коснуться слова «Патрики»**. Откроется вход по email и паролю.

В админке:
- **Заказы:** новые со звуком, статусы «Готовим → В пути → Доставлен», отмена.
- **Меню и цены:** цена правится прямо в строке, переключатель «в наличии» работает как стоп-лист. Можно добавлять и удалять позиции и категории, загружать фото, отмечать хиты.
- **Заведения:** адрес, телефон, часы, стоимость доставки, минимальный заказ, время, приём заказов вкл/выкл.

## Первая настройка (один раз)

### 1. База данных
Supabase → **SQL Editor** → New query → вставить весь файл `supabase/setup-all.sql` → **Run**.
Скрипт создаёт таблицы, права доступа, хранилище фото и стартовое меню (47 позиций с Menusa). Повторный запуск безопасен.

### 2. Учётная запись управляющего
1. Supabase → **Authentication → Users → Add user → Create new user**: email и пароль, галочка **Auto Confirm User**.
2. В **SQL Editor** выполнить, подставив email:
   ```sql
   insert into public.admins (user_id) select id from auth.users where email = 'ваш@email.ru';
   ```
3. **Не выключайте** «Allow new users to sign up» (Authentication → Sign In / Providers): через неё гости получают профиль. Права управляющего даёт только строка в таблице `admins`, поэтому обычная регистрация доступа к админке не открывает.

### 2а. Профили гостей и вход по номеру (обновление 002)
Уже включено в `setup-all.sql`. Для существующей базы — выполнить `supabase/002-profiles.sql`.
В Supabase должны быть включены: **Allow anonymous sign-ins**, провайдер **Phone** и хук **Send SMS → public.pk_send_sms**.
Пока SMS-сервис не подключён (`SMS_TEST_MODE: true` в `www/js/config.js`), коды подтверждения видны управляющему в админке (вкладка «Заказы») и приходят в Telegram-чат.
Подключить SMS.ru/SMSC: дописать отправку в функцию `pk_send_sms` через `net.http_post`, затем поставить `SMS_TEST_MODE: false`.

### 2б. Подтверждение номера: Telegram-бот и звонок (обновление 007)
Гость выбирает: «Через Telegram» (бот @PatrikiPubBot, бесплатно) или «Позвонить мне» (звонок-сброс, код — последние 4 цифры номера).
Логика — в серверной функции `verify` (разворачивается **с выключенной проверкой JWT**). Вебхук бота указывает на `https://<проект>.supabase.co/functions/v1/verify` с секретом из `app_secrets.telegram_webhook_secret`.
Звонок пока в тестовом режиме (`CALL_PROVIDER` не задан = `mock`): звонка нет, код виден в админке и в теме «Все заказы». Подключить SMS.ru: Edge Functions → Secrets → `CALL_PROVIDER = smsru`, `SMSRU_API_ID = ключ из кабинета SMS.ru`.

### 2б-1. Безопасность подтверждения звонком (обновление 014)
Тестовый режим входящего звонка подтверждал любой номер без звонка, а через это можно было войти в чужой профиль. Теперь подтверждение звонком работает, только если подключён New-Tel (`CALL_PROVIDER = newtel`). До подключения гостю предлагается Telegram.
Для проверки на тестовом проекте можно временно включить старое поведение: Secrets → `VERIFY_TEST_AUTOCONFIRM = true`. **На рабочем сервере не включать.**

### 2в. Карта гостя — своя программа лояльности (обновление 008)
- Правила задаёт владелец: админка → вкладка **«Баллы»** (уровни «от суммы покупок → %», лимит оплаты баллами, мин. заказ, бонусы, сгорание). Изменения действуют сразу.
- Гость: «Профиль → Карта гостя» — баланс, уровень, QR-код (код в нём меняется каждые 30 секунд), история.
- **В пабе:** админка → **«Касса · QR»** (доступна управляющему своей точки): сканировать QR камерой телефона или USB/Bluetooth-сканером, либо ввести номер карты / телефон → сумма чека → «Провести». Списать баллы гостя приложения можно только по его QR (по телефону или номеру карты — только начислить); гостям из MACE без приложения — по телефону, как раньше.
- **В приложении:** баллы начисляются, когда заказ переходит в «Доставлен»; при оформлении можно оплатить часть баллами; при отмене списанные баллы возвращаются.

**Интеграция с кассой iiko.** API готов, ключ — `select value from app_secrets where key = 'pos_api_key';` (передавать только интегратору).
```
POST https://ozbdmczmpejyctezxrdk.supabase.co/rest/v1/rpc/pos_lookup
  headers: apikey: <publishable key>, Content-Type: application/json
  body: {"p_key": "<ключ>", "p_code": "<строка из QR / номер карты / телефон>"}
  → {"name", "card_no", "balance", "tier": {"name","pct"}, "max_redeem_pct", "active"}

POST .../rest/v1/rpc/pos_accrue
  body: {"p_key": "<ключ>", "p_code": "...", "p_amount": 2500, "p_redeem": 0, "p_venue": "petrogradka", "p_check_id": "<id чека iiko>"}
  → начислено/списано; повтор с тем же p_check_id не начислит второй раз
```
На стороне iiko нужен плагин iikoFront (Front API) или обработчик вебхука iiko Cloud: бармен сканирует QR гостя сканером → плагин вызывает `pos_lookup`, показывает баланс; при закрытии заказа — `pos_accrue` с суммой и номером чека. Это делает интегратор iiko (дилер) по этому описанию.

### 3. Telegram (необязательно)
1. В Telegram написать @BotFather → `/newbot` → получить токен.
2. Добавить бота в чат заведения, написать в чат любое сообщение. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти там `"chat":{"id":-100…}`.
3. В SQL Editor:
   ```sql
   insert into public.app_secrets (key, value) values
     ('telegram_bot_token', 'ТОКЕН'),
     ('telegram_chat_id',  'ID_ЧАТА')
   on conflict (key) do update set value = excluded.value;
   ```

### 3а. Два заведения: управляющие и чаты (обновление 005)
Заказ видит только управляющий своей точки и владелец. Управляющий может: принимать заказы своей точки, вести её стоп-лист, менять часы, время доставки, телефон и включать/выключать приём заказов. Цены, меню, стоимость доставки и онлайн-оплату меняет только владелец.

1. **Authentication → Users → Add user** — email и пароль управляющего (пароль задаёте сами и передаёте ему).
2. В SQL Editor привязать к точке (`petrogradka` или `murino`; владелец — `null`):
   ```sql
   insert into public.admins (user_id, venue_id, name)
   select id, 'petrogradka', 'Управляющий Петроградки' from auth.users where email = 'почта@управляющего'
   on conflict (user_id) do update set venue_id = excluded.venue_id, name = excluded.name;
   ```
3. Свой Telegram-чат у каждой точки (бот один и тот же), а `telegram_chat_id` — общий чат владельца, туда приходят копии всех заказов:
   ```sql
   insert into public.app_secrets (key, value) values
     ('telegram_chat_id:petrogradka', 'ID_ЧАТА_ПЕТРОГРАДКИ'),
     ('telegram_chat_id:murino',      'ID_ЧАТА_МУРИНО')
   on conflict (key) do update set value = excluded.value;
   ```
   Вместо трёх групп можно одну группу с темами: значение — `ID_ГРУППЫ/НОМЕР_ТЕМЫ`, например `-1003918270228/4` (обновление 006).
4. Если гость ошибся точкой — у нового заказа кнопка «Передать → …»: заказ уходит в другую точку и её чат.

### 3б. Приложение для официантов (обновление 019)
Адрес: **https://patrikipab.ru/waiter/** — открыть на телефоне официанта и «Добавить на экран Домой». Официант входит по своему ПИН-коду, выбирает зал и стол, набирает заказ из меню iiko и отправляет: заказ появляется на кассе iikoFront на этом столе и сразу печатается на кухне/баре (сервисная печать). Если стол уже занят, заказ уходит дозаказом к открытому заказу. Без интернета заказ остаётся в очереди на телефоне и уходит сам.

- **Сервер:** функция `waiter` (проверка JWT **выключена**, своя авторизация по ПИН), таблицы `waiter_*` — `supabase/019-waiter.sql`.
- **Ключи iiko** — свои, отдельно от доставки: `app_secrets` → `waiter_iiko_api_key` (интеграция «Официант-приложение» в iikoWeb → Cloud API), `waiter_iiko_app_id` и `waiter_iiko_client_secret` (приложение «Официант-приложение» на портале api.iiko.help).
- **Меню** — внешнее меню iiko «Официант» (iikoWeb → Внешние заказы → Внешние меню), подключено к ключу официантов. Группы «Доставка – …» в приложении скрыты. Поменяли меню в iikoWeb — в приложении ☰ → «Обновить меню и столы» (само обновляется раз в 10 минут).
- **Сотрудники и ПИН** — управляющий в приложении: ☰ → «Сотрудники и ПИН-коды» → «Из сотрудников iiko» (выбрать человека из iiko и задать ПИН) или «Вручную». Уволенный в iiko сотрудник отключается в приложении сам. Или в SQL: `select public.waiter_upsert('Имя', '1234');`
- **Автообновление** — сборка подставляет номер в `www/waiter/waiter.js` и пишет `www/waiter/version.json`; приложение раз в 3 минуты проверяет номер и само перезагружается, когда официант на экране столов (корзины и очередь хранятся в телефоне). Обязательная переустановка Android-оболочки — поднять `apk_min` в `www/waiter/update.json`.
- **Android-приложение** «Официант Патрики» (`ru.patriki.waiter`) — `.github/workflows/waiter-apk.yml`, ссылка: https://github.com/plintus171993-lang/patriki-app/releases/download/waiter-latest/patriki-waiter.apk (на Android эта ссылка есть и на экране входа). Внутри — тот же /waiter/, поэтому обновления приходят сами; пересобирать APK нужно только при изменении оболочки (Actions → «Waiter APK» → Run workflow).
- **Касса должна быть на связи с облаком iiko** (iikoFront запущен, плагин iikoTransport работает): иначе iiko держит заказ 60 секунд и отменяет. Статус кассы виден в шапке приложения.

### 3в. Сайт веселый-патрик.рф (обновление 020)
Исходники сайта — папка `site/` (публикуется отдельно, см. `site/README.md`). Сайт работает на той же базе: меню, доставка, бронь, вход по номеру, карта гостя.
Своё у сайта — таблицы `news` (новости, акции, афиша) и `event_requests` (заявки на дни рождения, корпоративы, свадьбы, аренду зала) — `supabase/020-site.sql`.
Заявки приходят в Telegram-чат паба и в общий чат владельца; в админке — вкладка **«Сайт»**: заявки (взять в работу / проведено) и редактор новостей (только владелец).

### 3г. CRM «Патрики Офис» — кассы, табель, зарплата (обновление 023)
Адрес: **https://patrikipab.ru/office/** — веб-панель для владельца и управляющих (компьютер, планшет, телефон). Вход — те же email и пароль, что у управляющего в приложении доставки.
- **Кассы и деньги** — остатки касс, приход/расход по категориям, перемещения между кассами (деньги списываются сразу, в кассу получателя приходят после «Получено»).
- **Табель** — сетка «сотрудник × день»; у каждой смены своё заведение, поэтому видно, кто в какой день на какой точке.
- **Зарплата** — ведомости по месяцам и предварительный расчёт по табелю и ставкам; **Мотивация** — правила премий (пороги выручки, сервисный сбор, % шефа).
- **Журнал действий** — все изменения касс, табеля и сотрудников (видит владелец).
- **Автономно, без участия человека:** каждый час задача `crm-sync-hourly` (pg_cron в Supabase) вызывает функцию `crm-sync` и перезабирает из iiko выручку за вчера и сегодня по способам оплаты (тип «Рубли» не учитывается). Код — `supabase/functions/crm-sync`, база — `supabase/023-crm.sql` и `supabase/025-crm-money.sql`.
- **Раз в неделю бухгалтер:** «Зарплата» → «⇪ Выписка банка» (kl_to_1c.txt из СберБизнеса) и «⇪ Реестр зарплаты» после каждой выплаты по зарплатному проекту. Зарплата из банка засчитывается сотруднику один раз, эквайринг на счёт — перемещение из кассы «Банковские карты».
- Права управляющего: своя точка + отдельные права в `crm_manager_perms` (`cash.view`, `cash.add`, `cash.transfer`, `revenue.view`, `payroll.view`). Схема — `supabase/023-crm.sql`.

### 3д. «Себестоимость» — контроль техкарт и цен поставщиков (обновление 028)
Раздел в «Патрики Офис» (patrikipab.ru/office/#cost) — забирает у калькуляторщика рутинные проверки. Только читает iiko, ничего в него не пишет.
- **Каждую ночь (04:20 МСК)** задача `cost-check-nightly` вызывает функцию `cost-check`: номенклатура, действующие техкарты, продажи блюд за 30 дней (OLAP), приходные накладные за 120 дней. Находит:
  - **без техкарты** — блюдо продаётся, а техкарты нет (продажа ничего не списывает → недостача на инвентаризации);
  - **удалённый товар** в техкарте;
  - **фудкост** выше нормы — себестоимость по последним ценам прихода к средней цене продажи (кухня 35%, бар 30%, штучный товар бара 50%);
  - **подорожания** — цена в накладной выше прошлой поставки на 10% (срочно — от 25%);
  - **не закупается** — ингредиент техкарты не приходил больше 60 дней.
  Проблема, которой больше нет, закрывается сама. Управляющий может отметить «Не проблема» — строка уходит из сводки.
- **Инвентаризации** — вкладка с результатами за 120 дней по складам: недостача, излишки, итог; по клику — позиции с подсказками («повторяется N инвентаризаций», «возможен пересорт с …», «продаётся без техкарты: …»). Данные — OLAP по проводкам iiko (INVENTORY_CORRECTION), таблица `cost_inventory`. Пользователю iiko нужно право **B_VOTR** «Просматривать OLAP-отчет по проводкам».
- **Сводки в Telegram нет** — всё в разделе Офиса (функция умеет `digest`, но по расписанию не шлёт).
- **Строка → карточка блюда:** клик по позиции открывает текущую техкарту из iiko с ценами и себестоимостью; её можно поправить в CRM (сохраняется черновиком во «Техкарты шефа», есть печать) и открыть блюдо в iikoWeb для исправления.
- **Все блюда** — последняя вкладка «Себестоимости»: каждое блюдо iiko с ценой (средняя за 30 дней с учётом скидок), себестоимостью по техкарте и последним ценам прихода, фудкостом к норме, маржой с порции и за 30 дней. Сверху «срочно» (нет техкарты, удалённый товар, фудкост сильно выше нормы), затем «внимание» (фудкост выше нормы, нет цены прихода, подорожал ингредиент, давно не закупался), затем остальные — от самых невыгодных к самым выгодным. Порядок можно сменить: маржа с порции, заработали за 30 дней, выручка. Блюда без продаж за 30 дней скрыты галочкой. Таблица `cost_menu` пересчитывается при каждой проверке (`030-cost-menu.sql`).
- **Новая техкарта** — кнопка «＋ Новая техкарта»: шеф пишет состав текстом, каждый ингредиент с новой строки («Джим бим 40 мл», «котлета говяжья 180 г (жарка)», «2 ломтика чеддера»). CRM без ИИ разбирает количество и единицы, подбирает товары и заготовки iiko по похожим названиям (с учётом латиницы и редкости слов), сомнительные строки подсвечивает «Проверьте товар» с вариантами, ненайденные — «выберите товар». Дальше всё как раньше: брутто/нетто в единицах iiko, себестоимость по последним ценам прихода, фудкост; статусы черновик → утверждена → занесена в iiko; «Печать». В iiko сама не пишет. Запас на будущее: разбор через ИИ (action `card_parse` / `job_start` в `cost-check`) остался в коде, но из Офиса не вызывается — подключается отдельно, нужен ключ ИИ в `app_secrets`.
- **Права:** владелец — всё и «Пороги»; управляющему — галочка «Себестоимость» (`cost.view`) во вкладке «Доступы».
- **Установка:** выполнить `supabase/028-cost.sql`; развернуть функцию `cost-check` **с выключенной проверкой JWT**; заново развернуть `crm-users` (в ней новое право). 
- **Права пользователя iiko** (`iiko_server_login`): чтение номенклатуры и техкарт, приходных накладных, OLAP-отчётов. Если права нет, ошибка в разделе назовёт его — выдать в iikoOffice.
- Первую проверку — кнопкой «Проверить сейчас» в разделе и сверить результат с iiko. Если вверху горит «без продаж» — OLAP не отдал продажи по блюдам (имена полей отличаются в версии iiko); остальные проверки работают, фудкост и фильтр «продаётся» — нет.

### 5. Ключ подписи Android (до раздачи гостям!)
Без него каждая сборка подписывается новым случайным ключом, и обновления не встанут поверх старой версии. Создать ключ один раз и **хранить копию в надёжном месте**:
```bash
keytool -genkeypair -v -keystore patriki.jks -alias patriki -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 patriki.jks > patriki.jks.b64
```

## Демо-режим
Если открыть приложение с `?demo` в адресе, оно работает без сервера: меню и заказы хранятся в браузере, пароль админки — `patriki`.

## Безопасность
- Цены пересчитывает сервер: подменить цену в заказе нельзя.
- Гость не видит чужие заказы. Меню и заказы меняет только учётная запись из таблицы `admins`.
- В приложении лежит только публичный ключ. Секретный `service_role` ключ и токен Telegram наружу не попадают.
