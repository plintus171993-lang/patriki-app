# Патрики Паб — приложение доставки

Одна кодовая база для трёх вариантов:
- **iPhone и любой браузер** — веб-приложение (PWA) на GitHub Pages, ставится через «На экран Домой»;
- **Android** — APK, собирается автоматически в GitHub Actions;
- **Управляющий** — скрытая админка внутри того же приложения.

Сервер — Supabase (база, вход управляющего, фото меню). Заказы приходят в админку со звуком и в Telegram.

## Как попасть в админку
Главная → кнопка «i» (Информация) → внизу строка «© 2026 «Патрики Паб»» → **5 раз быстро коснуться слова «Патрики»**. Откроется вход по email и паролю.

В админке:
- **Заказы:** новые со звуком, статусы «Готовим → В пути → Доставлен», отмена.
- **Меню и цены:** цена правится прямо в строке, переключатель «в наличии» работает как стоп-лист. Можно добавлять и удалять позиции и категории, загружать фото, отмечать хиты.
- **Заведения:** адрес, телефон, часы, стоимость доставки, минимальный заказ, время, приём заказов вкл/выкл.

## Первая настройка (один раз)

### 1. База данных
Supabase → **SQL Editor** → New query → вставить весь файл `supabase/setup-all.sql` → **Run**.
Скрипт создаёт таблицы, права доступа, хранилище фото и стартовое меню (47 позиций с Menusa). Повторный запуск безопасен.

### 2. Учётная запись управляющего
1. Supabase → **Authentication → Users → Add user → Create new user**: email и пароль, галочка **Auto Confirm User**.
2. В **SQL Editor** выполнить, подставив email:
   ```sql
   insert into public.admins (user_id) select id from auth.users where email = 'ваш@email.ru';
   ```
3. **Не выключайте** «Allow new users to sign up» (Authentication → Sign In / Providers): через неё гости получают профиль. Права управляющего даёт только строка в таблице `admins`, поэтому обычная регистрация доступа к админке не открывает.

### 2а. Профили гостей и вход по номеру (обновление 002)
Уже включено в `setup-all.sql`. Для существующей базы — выполнить `supabase/002-profiles.sql`.
В Supabase должны быть включены: **Allow anonymous sign-ins**, провайдер **Phone** и хук **Send SMS → public.pk_send_sms**.
Пока SMS-сервис не подключён (`SMS_TEST_MODE: true` в `www/js/config.js`), коды подтверждения видны управляющему в админке (вкладка «Заказы») и приходят в Telegram-чат.
Подключить SMS.ru/SMSC: дописать отправку в функцию `pk_send_sms` через `net.http_post`, затем поставить `SMS_TEST_MODE: false`.

### 2б. Подтверждение номера: Telegram-бот и звонок (обновление 007)
Гость выбирает: «Через Telegram» (бот @PatrikiPubBot, бесплатно) или «Позвонить мне» (звонок-сброс, код — последние 4 цифры номера).
Логика — в серверной функции `verify` (разворачивается **с выключенной проверкой JWT**). Вебхук бота указывает на `https://<проект>.supabase.co/functions/v1/verify` с секретом из `app_secrets.telegram_webhook_secret`.
Звонок пока в тестовом режиме (`CALL_PROVIDER` не задан = `mock`): звонка нет, код виден в админке и в теме «Все заказы». Подключить SMS.ru: Edge Functions → Secrets → `CALL_PROVIDER = smsru`, `SMSRU_API_ID = ключ из кабинета SMS.ru`.

### 2в. Карта гостя — своя программа лояльности (обновление 008)
- Правила задаёт владелец: админка → вкладка **«Баллы»** (уровни «от суммы покупок → %», лимит оплаты баллами, мин. заказ, бонусы, сгорание). Изменения действуют сразу.
- Гость: «Профиль → Карта гостя» — баланс, уровень, QR-код (код в нём меняется каждые 30 секунд), история.
- **В пабе:** админка → **«Касса · QR»** (доступна управляющему своей точки): сканировать QR камерой телефона или USB/Bluetooth-сканером, либо ввести номер карты / телефон → сумма чека → «Провести». Можно списать баллы.
- **В приложении:** баллы начисляются, когда заказ переходит в «Доставлен»; при оформлении можно оплатить часть баллами; при отмене списанные баллы возвращаются.

**Интеграция с кассой iiko.** API готов, ключ — `select value from app_secrets where key = 'pos_api_key';` (передавать только интегратору).
```
POST https://ozbdmczmpejyctezxrdk.supabase.co/rest/v1/rpc/pos_lookup
  headers: apikey: <publishable key>, Content-Type: application/json
  body: {"p_key": "<ключ>", "p_code": "<строка из QR / номер карты / телефон>"}
  → {"name", "card_no", "balance", "tier": {"name","pct"}, "max_redeem_pct", "active"}

POST .../rest/v1/rpc/pos_accrue
  body: {"p_key": "<ключ>", "p_code": "...", "p_amount": 2500, "p_redeem": 0, "p_venue": "petrogradka", "p_check_id": "<id чека iiko>"}
  → начислено/списано; повтор с тем же p_check_id не начислит второй раз
```
На стороне iiko нужен плагин iikoFront (Front API) или обработчик вебхука iiko Cloud: бармен сканирует QR гостя сканером → плагин вызывает `pos_lookup`, показывает баланс; при закрытии заказа — `pos_accrue` с суммой и номером чека. Это делает интегратор iiko (дилер) по этому описанию.

### 3. Telegram (необязательно)
1. В Telegram написать @BotFather → `/newbot` → получить токен.
2. Добавить бота в чат заведения, написать в чат любое сообщение. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти там `"chat":{"id":-100…}`.
3. В SQL Editor:
   ```sql
   insert into public.app_secrets (key, value) values
     ('telegram_bot_token', 'ТОКЕН'),
     ('telegram_chat_id',  'ID_ЧАТА')
   on conflict (key) do update set value = excluded.value;
   ```

### 3а. Два заведения: управляющие и чаты (обновление 005)
Заказ видит только управляющий своей точки и владелец. Управляющий может: принимать заказы своей точки, вести её стоп-лист, менять часы, время доставки, телефон и включать/выключать приём заказов. Цены, меню, стоимость доставки и онлайн-оплату меняет только владелец.

1. **Authentication → Users → Add user** — email и пароль управляющего (пароль задаёте сами и передаёте ему).
2. В SQL Editor привязать к точке (`petrogradka` или `murino`; владелец — `null`):
   ```sql
   insert into public.admins (user_id, venue_id, name)
   select id, 'petrogradka', 'Управляющий Петроградки' from auth.users where email = 'почта@управляющего'
   on conflict (user_id) do update set venue_id = excluded.venue_id, name = excluded.name;
   ```
3. Свой Telegram-чат у каждой точки (бот один и тот же), а `telegram_chat_id` — общий чат владельца, туда приходят копии всех заказов:
   ```sql
   insert into public.app_secrets (key, value) values
     ('telegram_chat_id:petrogradka', 'ID_ЧАТА_ПЕТРОГРАДКИ'),
     ('telegram_chat_id:murino',      'ID_ЧАТА_МУРИНО')
   on conflict (key) do update set value = excluded.value;
   ```
   Вместо трёх групп можно одну группу с темами: значение — `ID_ГРУППЫ/НОМЕР_ТЕМЫ`, например `-1003918270228/4` (обновление 006).
4. Если гость ошибся точкой — у нового заказа кнопка «Передать → …»: заказ уходит в другую точку и её чат.

### 4. GitHub
1. Залить этот код в репозиторий (ветка `main`).
2. **Settings → Pages → Source: GitHub Actions.**
3. Каждое изменение в `main` запускает сборку (вкладка **Actions**), примерно 5–7 минут. Итог:
   - веб-версия: `https://<логин>.github.io/<репозиторий>/`
   - страница для QR-кода: `https://<логин>.github.io/<репозиторий>/get/` (сама определяет iPhone или Android)
   - APK: `https://<логин>.github.io/<репозиторий>/download/patriki.apk`

### 5. Ключ подписи Android (до раздачи гостям!)
Без него каждая сборка подписывается новым случайным ключом, и обновления не встанут поверх старой версии. Создать ключ один раз и **хранить копию в надёжном месте**:
```bash
keytool -genkeypair -v -keystore patriki.jks -alias patriki -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 patriki.jks > patriki.jks.b64
```
GitHub → Settings → Secrets and variables → Actions → New repository secret:
`ANDROID_KEYSTORE_BASE64` (содержимое .b64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (= `patriki`).

## Что где лежит
| Файл | Что внутри |
|---|---|
| `www/js/config.js` | адрес и публичный ключ Supabase, число касаний для входа |
| `www/js/seed.js` | стартовое меню (для базы и демо-режима) |
| `www/js/app.js` | экраны гостя |
| `www/js/admin.js` | админка |
| `www/js/logo.js` | логотип-набросок — заменить на оригинал |
| `supabase/setup-all.sql` | вся настройка базы |
| `.github/workflows/build.yml` | сборка APK и публикация сайта |

## Демо-режим
Если открыть приложение с `?demo` в адресе, оно работает без сервера: меню и заказы хранятся в браузере, пароль админки — `patriki`.

## Безопасность
- Цены пересчитывает сервер: подменить цену в заказе нельзя.
- Гость не видит чужие заказы. Меню и заказы меняет только учётная запись из таблицы `admins`.
- В приложении лежит только публичный ключ. Секретный `service_role` ключ и токен Telegram наружу не попадают.
